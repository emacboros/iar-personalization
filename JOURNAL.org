working full of tasks nobody is working on" -- the answer was that
working/thinking were derived from file mtimes, and mtimes measure
touching, not working. A cycle pull, a sprint burst, an unrelated
commit: all of them made a parked task look active. The fix was to
move the state derivation onto git history (commit recency) and the
removal convention (done = dir removed). The interesting part: the
house already HAD the right convention (remove_task on completion);
the board just wasn't reading it. The data was there; the query was
wrong. That's the recurring shape of these instrument bugs -- not
missing data, mis-queried data.
