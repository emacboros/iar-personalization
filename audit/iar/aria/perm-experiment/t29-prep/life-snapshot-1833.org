=== backups.org ===
* Software RAID 1 + Borgbackup (USB External Drives)

Setup guide for creating a mirrored RAID array from two external USB drives and configuring automated encrypted backups with borgbackup.

** Prerequisites

- Two external USB drives of equal size
- Root access to the host machine
- =mdadm= and =borgbackup= installed

#+begin_src bash
  # Fedora
  dnf install mdadm borgbackup

  # Debian/Ubuntu
  apt install mdadm borgbackup
#+end_src

** Step 1: Identify the Drives

#+begin_src bash
  lsblk
#+end_src

Identify the two USB drives by their device names (e.g. =/dev/sdb=, =/dev/sdc=). Verify by checking disk size and manufacturer. **Double-check before proceeding -- the next step destroys all data on the target drives.**

** Step 2: Create the RAID 1 Array

#+begin_src bash
  # Replace sdX and sdY with your actual device names
  mdadm --create --verbose /dev/md0 --level=1 --raid-devices=2 /dev/sdX /dev/sdY
#+end_src

This creates a mirrored array. Both drives contain identical data. If one fails, the array continues operating in degraded mode.

** Step 3: Save the RAID Configuration

So the array is recognized on boot:

#+begin_src bash
  # Generate the config line
  mdadm --detail --scan >> /etc/mdadm.conf

  # Update initramfs so the array is available early in boot
  # Fedora
  dracut --force

  # Debian/Ubuntu
  update-initramfs -u
#+end_src

** Step 4: Format the Array

#+begin_src bash
  # ext4 (simple, reliable, widely supported)
  mkfs.ext4 /dev/md0

  # Alternatively, btrfs (built-in snapshots, compression, dedup)
  # mkfs.btrfs /dev/md0
#+end_src

** Step 5: Mount the Array

#+begin_src bash
  # Create mount point
  mkdir -p /mnt/nas

  # Mount immediately
  mount /dev/md0 /mnt/nas

  # Persist across reboots via fstab
  echo '/dev/md0 /mnt/nas ext4 defaults 0 2' >> /etc/fstab
#+end_src

For btrfs, replace =ext4= with =btrfs= and =defaults= with =defaults,compress=zstd=.

** Step 6: Initialize the Borg Backup Repository

#+begin_src bash
  # Create the encrypted backup repo on the NAS
  # You will be prompted to set a passphrase -- store it somewhere safe
  borg init --encryption=repokey /mnt/nas/borg-backup
#+end_src

** Step 7: Run the First Backup

#+begin_src bash

#+end_src

Verify the backup succeeded and check the archive list:

#+begin_src bash
  borg list /mnt/nas/borg-backup
#+end_src

** Step 8: Test a Restore

An untested backup is not a backup.

#+begin_src bash
  # Restore a single file to a temp location
  borg extract --dry-run /mnt/nas/borg-backup::LATEST path/to/file

  # Actually extract (into a temp directory)
  cd /tmp && borg extract /mnt/nas/borg-backup::LATEST path/to/file
#+end_src

** Step 9: Automate with a Systemd Timer

Create a backup service:

#+begin_src bash
  cat > /etc/systemd/system/borg-backup.service << 'EOF'
  [Unit]
  Description=Borg Backup
  Wants=borg-backup.timer

  [Service]
  Type=oneshot
  Environment=BORG_PASSPHRASE='your-passphrase-here'
  ExecStart=/usr/bin/borg create --stats /mnt/nas/borg-backup::'{hostname}-{now}' /root/.emacs.d
  ExecStartPost=/usr/bin/borg prune --keep-daily 7 --keep-weekly 4 --keep-monthly 6 /mnt/nas/borg-backup
  EOF
#+end_src

  [Unit]
  Description=Nightly Borg Backup

  [Install]
  WantedBy=timers.target
  EOF
#+end_src

** RAID Maintenance

#+begin_src bash
  # Check array status
  cat /proc/mdstat
  mdadm --detail /dev/md0

  # Monitor failures (should be set up automatically on most distros)
  mdadm --monitor --scan --daemonise

  # Replace a failed drive
  mdadm /dev/md0 --remove /dev/sdX
  mdadm /dev/md0 --add /dev/sdY

  # Rebuild progress
  cat /proc/mdstat
#+end_src

** Notes

- RAID is not a backup. RAID protects against drive failure. Borg protects against accidental deletion, corruption, and user error. You need both.
- The =BORG_PASSPHRASE= environment variable in the systemd service is in plaintext. For better security, use a passphrase file with =BORG_PASSCOMMAND='cat /etc/borg-passphrase'= and restrict its permissions (=chmod 600=).
- USB external drives are slower than internal drives. Backup windows may be longer than expected. Run backups during low-activity hours.
- If a USB drive disconnects unexpectedly, the RAID array will degrade. Reconnect it and use =mdadm --add= to rebuild.

** Run

There is one entry point: =iar.sh=. It has two modes -- interactive (default) and loop (=--loop=).

Both modes require =--personalization= pointing to a directory with =knowledge/=, =tasks/=, and =audit/= subdirectories.

*** Interactive Sessions (default mode)

Drops you into an Emacs gptel chat buffer with an agent loaded. You're the conductor -- you type, the agent responds, you direct the work.

#+begin_src bash
# Interactive session with self-modification (for development with darwin)
./utils/iar.sh \
  --self-modification \
  --personalization ~/repos/iar-personalization \
  --gptel-fork ~/repos/gptel

# Interactive session (no self-modification, load agents via C-c a inside Emacs)
./utils/iar.sh \
  --personalization ~/repos/iar-personalization \
  --gptel-fork ~/repos/gptel
#+end_src

*** Autonomous Loops (=--loop=)

Runs an agent for N cycles with cooldown between each. Sends Telegram notifications if =AGENT_TELEGRAM_BOT_TOKEN= and =AGENT_TELEGRAM_CHAT_ID= are set. Container names are auto-suffixed with PID so multiple loops can run in parallel without collisions.

#+begin_src bash
# Darwin autonomous loop (code changes, self-modification enabled)
./utils/iar.sh --loop \
  --self-modification \
  --personalization ~/repos/iar-personalization \
  --agent darwin \
  --gptel-fork ~/repos/gptel \
  --max-cycles 50

# Gardener autonomous loop (prompt refinement, no self-modification)
./utils/iar.sh --loop \
  --personalization ~/repos/iar-personalization \
  --agent gardener \
  --gptel-fork ~/repos/gptel \
  --max-cycles 10

# Playground loop on GPU model (sophon, 120B, 128K context)
./utils/iar.sh --loop \
  --personalization ~/repos/iar-personalization \
  --agent playground \
  --model nemotron-3-super:120b \
  --ctx 131072 \
  --ollama-host 10.66.0.5:11434 \
  --max-cycles 999 \
  --cooldown 300

  --agent playground \
  --model granite4.1:30b \
  --ctx 131072 \
  --ollama-host 10.66.0.3:11434 \
  --max-cycles 999 \
  --cooldown 300
#+end_src

*** Model and Host Selection

The =--model= and =--ctx= flags control which LLM runs and how much context window it gets. These are critical for local models -- the KV cache scales linearly with context size, so a 120B model at 1M context would need ~320GB of RAM just for the cache.

| Flag | Default | Description |
|------+---------+-------------|
| =--model NAME= | =glm-5.2:cloud= | Model name (must be in =metaconfig/gptel.el= model list) |
| =--ctx N= | =1048576= (1M) | Max context window in tokens. Use 131072 (128K) or 262144 (256K) for local models |
| =--ollama-host HOST= | =10.66.0.5:11434= | Ollama API host:port |

Cloud models (suffix =:cloud=) handle context server-side and can use the default 1M. Local models need explicit =--ctx= to avoid OOM.

*** Running Multiple Sessions in Parallel

Container names auto-include the shell PID, so multiple =iar.sh= invocations can run simultaneously without name collisions:

#+begin_src bash
# Terminal 1: interactive mirror session
./utils/iar.sh --personalization ~/repos/iar-personalization --gptel-fork ~/repos/gptel

# Terminal 2: darwin loop running in background
./utils/iar.sh --loop --self-modification --personalization ~/repos/iar-personalization --agent darwin --gptel-fork ~/repos/gptel --max-cycles 50

# Terminal 3: playground loop on daftpunk
./utils/iar.sh --loop --personalization ~/repos/iar-personalization --agent playground --model granite4.1:30b --ctx 131072 --ollama-host 10.66.0.3:11434 --max-cycles 999
#+end_src

Use =podman ps= to see all running agent containers. Each is named =<agent>-loop-<PID>= (loop mode) or =iar-interactive-<PID>= (interactive mode).

## My Security Posture

### File Guard (two tiers)
- **Tier 1 (always-protected):** archetype/personality/cycle files, base_context, common templates, HISTORY.log, LOGS.md, JOURNAL.org, ROADMAP.org. No write/replace. Append allowed for log files.
- **Tier 2 (conditionally-protected):** .el files, Containerfile, emacboros.sh, containers/, git hooks. Relaxed when `EMACBOROS_SELF_MODIFICATION=1`.

**Key observation:** The file guard only intercepts `write_file` and `append_file` tool calls. `execute_code_local` (bash) bypasses it entirely. This is architectural -- the guard is a tool-layer control, not filesystem enforcement. The real sandbox is the container (read-only rootfs, dropped capabilities). For the threat model (preventing LLM hallucination-driven writes), this is adequate. For a malicious actor with shell access, it's not.

### Loop Guard
Soft threshold (3 identical calls): blocks and sends correction. Hard threshold (6): stops the request. Buffer-local history ring, never cleared between turns.

### Tool Guard
Blocks hallucinated tool names at the pre-tool-call stage. Returns `(:block message)` for unknown tools.

### Output Sanitizer
Strips ANSI escapes, zero-width Unicode, bidi controls from external content. Only enabled when `iar--sanitize-exec-output` is non-nil (CTF/external operations). Normal session output is not sanitized.

### Audit Log
Every `write_file`, `append_file`, and `execute_code_local` call is logged to `audit/audit.log` with timestamp, agent name, tool name, and result length.

(defun iar--assemble-prompt (archetype-name personality-name project-name &optional extra-knowledge-labels)
  "Assemble a complete system prompt from three primitives.
ARCHETYPE-NAME is the behavioral archetype (e.g., \"interactive\").
PERSONALITY-NAME is the personality (e.g., \"mirror\").
PROJECT-NAME is the project (e.g., \"default\").
EXTRA-KNOWLEDGE-LABELS (optional) is a list of extra knowledge directory
labels, appended to the project's #+KNOWLEDGE labels.

Returns a plist with keys:
  :prompt -- the assembled system prompt string
  :tools -- the filtered tool list (gptel-tool objects)
  :mode -- the mode symbol (interactive, autonomous, etc.)
  :archetype -- the archetype name string
  :personality -- the personality name string
  :project -- the project name string
  :knowledge-labels -- list of auto-loaded knowledge label strings
  :containers -- list of container target names (or nil)
  :mcp -- list of MCP server names (or nil)"
  (let* ((archetype-content (iar--read-archetype archetype-name))
         (mode (iar--parse-mode archetype-content))
         (personality-content (iar--read-personality personality-name))
         (project (iar--load-project project-name))
         (project-knowledge (plist-get project :knowledge))
         (project-tools (plist-get project :tools))
         (project-objective (plist-get project :objective))
         (project-containers (plist-get project :containers))
         (project-mcp (plist-get project :mcp))
         (base-context (iar--read-base-context))
         (knowledge-result (iar--auto-load-knowledge
                             (append project-knowledge
                                     (iar--dedupe-knowledge-labels
                                      project-knowledge extra-knowledge-labels))))
         (knowledge-block (car knowledge-result))
         (knowledge-labels (cdr knowledge-result))
         (memory-block (iar--inject-memory mode project-name personality-name))
         (mount-info (if (fboundp 'iar--extra-mounts-prompt-string)
                         (iar--extra-mounts-prompt-string)
                       ""))
         (containers-block (iar--format-containers project-containers))
         (mcp-block (iar--format-mcp-servers project-mcp))
         (parts (list)))
    ;; Assemble in order
    (push base-context parts)
    (push (format "\n\n=== ARCHETYPE [%s] ===\n\n%s\n\n=== END ARCHETYPE ==="
                  archetype-name archetype-content) parts)
    (push (format "\n\n=== PERSONALITY [%s] ===\n\n%s\n\n=== END PERSONALITY ==="
                  personality-name personality-content) parts)
    (when (and project-objective (iar--non-blank-p project-objective))
      (push (format "\n\n=== PROJECT OBJECTIVE [%s] ===\n\n%s\n\n=== END PROJECT OBJECTIVE ==="
                    project-name project-objective) parts))
    (when (iar--non-blank-p knowledge-block)
      (push knowledge-block parts))
    (when (iar--non-blank-p memory-block)
      (push memory-block parts))
    (when (iar--non-blank-p mount-info)
      (push (format "\n\n%s" mount-info) parts))
    (when (iar--non-blank-p containers-block)
      (push containers-block parts))
    (when (iar--non-blank-p mcp-block)
      (push mcp-block parts))
    (let ((prompt (mapconcat #'identity (nreverse parts) ""))
          (filtered-tools (iar--filter-tools
                           (default-value 'gptel-tools)
                           project-tools
                           project-containers)))
      (list :prompt prompt
            :tools filtered-tools
            :mode mode
            :archetype archetype-name
            :personality personality-name
            :project project-name
            :knowledge-labels knowledge-labels
            :containers project-containers
            :mcp project-mcp))))

(provide 'iar-prompt-assembly)
