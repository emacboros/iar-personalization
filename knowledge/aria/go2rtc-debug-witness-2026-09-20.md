## How frigate/go2rtc config actually works (the mechanism, c167-verified)

1. go2rtc runs with TWO configs:
   `/usr/local/go2rtc/bin/go2rtc -config=/config/go2rtc_homekit.yml
   -config=/dev/shm/go2rtc.yaml`
2. `/dev/shm/go2rtc.yaml` is REGENERATED by frigate at every go2rtc
   start: the s6 run script (`/run/s6/db/servicedirs/go2rtc/run.user`)
   deletes any stale /dev/shm/go2rtc.yaml, then runs
   `python3 /usr/local/go2rtc/create_config.py`, which reads frigate's
   config.yaml, takes the `go2rtc:` section verbatim, adds defaults
   (api.origin, hass, log.format=text, webrtc.candidates, ffmpeg.bin),
   and writes /dev/shm/go2rtc.yaml.
3. Therefore: to change go2rtc's config PERSISTENTLY, edit frigate's
   config.yaml `go2rtc:` section and restart frigate. Editing
   /dev/shm/go2rtc.yaml directly works only until the next restart
   (and c167 confirmed the restart wipes it).
4. `/config/go2rtc_homekit.yml` is the PRIMARY config (writeback
   target for API PUTs -- the c166 pollution face). It is NOT
   regenerated. It was empty (0 bytes) after c166's cleanup; frigate
   recreated it empty at restart. Keep it empty; the real config
   lives in config.yaml.
