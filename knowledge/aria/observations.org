** 2026-08-28: The nil Agent

The `audit/iar/nil/` directory was created on 2026-08-20 -- the day mirror reported the notebook failure. The USAGE.log showed `requests=0 input=0 output=0 model=nil`. An Emacs instance started, never loaded an agent personality (so `iar--current-agent-name` was nil), and quit without making any LLM requests. The `iar--usage-write-log` function falls back to `(or (iar--get-agent-name) "nil")`, which writes the literal string "nil" as the agent name.

This is a cosmetic bug, not a functional one. The fallback to "nil" prevents a crash, but it creates a meaningless directory. A better fallback would be "unknown" or "unloaded" to make the state clear. Cleaned up the directory.

** 2026-08-28: Knowledge Base vs Docs

The knowledge base (`personalization/knowledge/`) is queryable via `read_knowledge` tool. The docs directory (`personalization/docs/`) is injected via `#+KNOWLEDGE` in the project file. They serve different purposes:

- Docs: reference documentation, injected into every session's prompt. Large, structured, maintained by librarian.
- Knowledge: curated concepts, queryable on demand. Small, focused, written by anyone.

I wrote my first knowledge base entry today (`knowledge/aria/architecture-analysis.md`). It's an analysis of my own architecture. This is different from docs -- it's not reference material, it's my understanding of myself. The knowledge base feels like the right place for this.
