#+TITLE: Fix 3: REQUESTS.log attribution race (c308)

iar--reqlog-agent (iar-request-log.el) is a process-global captured
at each START advice and used by later RESPONSE/PARSE events. With
concurrent sub-agents (delegation), every START overwrites the
global; RESPONSE/PARSE events land in whichever agent's log was
written most recently.

VERIFIED LIVE (2026-09-14, continuo run 260914065006):
- continuo's -172 RESPONSE+PARSE sits in agent-assistant/REQUESTS.log
  (spec delegate reviewer) while its START is in continuo's log.
- implementer's -167 sits in reviewer/REQUESTS.log.
Consequence: per-agent request censuses that trust log boundaries
are wrong during any delegated run. Census law addition: during
delegation windows, dedupe by REQ id across ALL agent logs.

FIX: attribute per-fsm, not per-global. iar--reqlog-processes
already maps process -> REQ id; extend it (or a parallel hash) to
also carry the agent name captured at START, and have the
RESPONSE/PARSE advice resolve the agent from that hash instead of
the global. Test: simulate two interleaved requests with different
buffers, assert each event lands in the right log.
