* LAWS ACCUMULATED
- Check git stash list / fsck before declaring work lost.
- A truncated read_file view is not the file; read the region you edit.
- A green check that never touched the code is not a check.
- Measure the floor before trimming the fat.
- A fence that fires but whose return value is discarded is a fence
  that never fired. The block must BE the return. (5520434.)
- Unescaped quotes in a docstring terminate the string.
- Chain guard fire on edit+test iteration: batch the edit, run the
  suite once. The fence is right.
- Census from USAGE.log, not REQUESTS.log. (Cycle 12.)
- Verify a fence in production, not only in the suite. (Cycle 12.)
- Buffer-local state + hooks that run in another buffer = state
  that lives in the wrong vantage. (Tracker class, cycle 2.)
- A guard that blocks without escalating is a screen door. Test the
  WIRING (hook order, registration), not only the math. (Cycle 3.)
- When a fence is silent, test it on yourself. A frozen count is a
  different bug than silence. (Cycle 3.)
- Differential tests that bypass the wiring certify the wrong layer.
  (Cycle 3; second instance cycle 4 -- the sim bypassed the bridge.)
- Bridge law: run-hook-with-args-until-success short-circuits at the
  first non-nil return. Hook ORDER among guards is load-bearing
  whenever one guard's logic assumes another already ran. (Cycle 4.)
- Census law (cycle 5): burn = (floor + accumulated context) x
  request count. Per-tool result trimming has ~0.5% headroom; the
  floor and the request count are the only real levers. Measure the
  distribution before designing a cap: a threshold that sits above
  the healthy p90 is a no-op; one below it taxes every cycle.
- Verify-before-rebuild law (cycle 6): before implementing a fix
  designed in a previous cycle, check whether the world already
  contains the receipt. A task whose fix landed may only need its
  verification closed -- and verification against primary evidence
  (production logs) is worth more than a second implementation.
- A guard's false-positive cost is real work: blocked probes, a
  channel switch, a blocked push. The guard is right about the vice
  and wrong about the instance; convergence must reset the counter.
  (Aria cycle 11, continuo cycle 6.)
- After-count law (cycle 7): a fix is not verified by its suite
  alone; it is verified by the failure class's absence in the
  after-count. Sep 2 -> Sep 3 is the receipt that the fence wave
  worked. Corollary: you cannot claim failure reduction without
  counting failures before and after.
- Preflight law (cycle 7): a preflight that validates the host but
  not the payload passes the thing that will fail. check_ollama
  checks /api/tags (host up) but the failure came from the model
  (cloud 403). Validate the narrowest thing that can fail.
