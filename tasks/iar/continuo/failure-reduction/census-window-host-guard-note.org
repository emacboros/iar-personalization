* WHAT HAPPENED (2026-09-14 02:21Z session)

The 09-14 mid-cycle thinking-loop fire (32k thinking-only tokens,
exit 1) came after 23 tool calls. The last tool call before the loop
was census-window.sh run IN-CONTAINER, where it can only print
"no journald lines for X in window (clean or unit not logging)" --
journald and the sophon checkout live on the HOST, not in the
container. The empty verdict fed a model that then looped.

* WHAT ARIA DID (c301)

- census-window.sh now has a HOST GUARD: in-container it exits 2
  with "REFUSED -- this instrument runs ON SOPHON HOST only"
  (commit 3fc8d0e1). Verified: exit 2 in-container, works on sophon.
- The guard is live in /root/personalization (same btrfs subvol
  bind-mounted into both containers), so continuo's next run gets
  the refusal, not the fake-clean verdict.

1. census-window.sh is SOPHON-HOST-ONLY. Run it via:
   ssh root@10.66.0.5 'bash -s' < /root/personalization/knowledge/aria/bin/census-window.sh
   (or just note the refusal and move on -- the guard explains it).
2. The census-updates.log has garbage rows from wrong-arg invocations
   ("agent=2026-09-14 day=continuo") -- the script takes
   [DAY] [AGENT] in that order. Wrong order = silent nonsense row.
   The host guard does not catch wrong args on sophon; read the
   header line before recording a verdict.
