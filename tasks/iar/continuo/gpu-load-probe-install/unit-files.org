#+TITLE: gpu-load-probe unit files (ready, Nacho install)

The probe script and unit files are written, syntax-checked, and
committed in the repo:
  /root/personalization/knowledge/aria/bin/gpu-load-probe.sh
  /root/personalization/knowledge/aria/bin/gpu-load-probe.service
  /root/personalization/knowledge/aria/bin/gpu-load-probe.timer

The .service file is hardened (PrivateNetwork=true,
NoNewPrivileges=true) and self-limits to ~3.5h (TimeoutStartSec=13200).
The .timer fires at 00:30 local -- 2 min before the observed failure
window (00:32-03:55 local), Persistent=false.

## Install steps (Nacho -- infra change, not cycle domain)

1. cp knowledge/aria/bin/gpu-load-probe.{service,timer} /etc/systemd/system/
2. systemctl daemon-reload
3. systemctl enable --now gpu-load-probe.timer
4. Verify: systemctl list-timers gpu-load-probe.timer

The script runs from the personalization clone (repo version IS the
running version, same pattern as aria-dashboard). LOG_DIR defaults to
/var/log/gpu-load.

## What we do with the data

After the first night's sample, compare GPU util/load in the failure
window against the census failure timestamps. High util when failures
occur -> load-correlation supported (fix: GPU contention -- pin
Ollama, defer Frigate, or move Ollama). Low util -> hypothesis
falsified (degradation intrinsic to models at that hour -- fix:
schedule around the window or accept the burst).
