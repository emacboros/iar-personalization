## The question
Does the block message actually reach the model's conversation
buffer? The cap hook returns (:block . message); gptel--handle-pre-tool
sets tool-call :error and passes the message as the tool RESULT via
gptel--process-tool-call. If the message is present in the buffer
and the model STILL ignores it, it is model non-compliance (a
watching item), NOT a machinery gap.

## The differential test
Write a test that pins the block->buffer flow:
1. A pre-tool-call hook returns (:block . "STOP CALLING TOOLS").
2. gptel--handle-pre-tool runs on a fake FSM with one pending tool call.
3. Assert the tool call's :result contains the block message and
   :error is t (the tool_call_error path).
4. Assert the message is inserted into the conversation buffer
   (or verify the mechanism that inserts it -- the model sees it).
