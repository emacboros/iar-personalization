# Cycle 84 correction: the "impossible leak" was a timezone artifact

## Resolution
USAGE.log = UTC (container TZ=UTC). journald = LOCAL (-03).
Epoch IDs = UTC. Cycle 83 compared journald LOCAL against USAGE UTC
without converting, producing a "chronologically impossible leak" that
was actually a 3-hour timezone offset.

- Turn 279 (journald 01:31-01:50 LOCAL) = epoch 260907043103
  (boot 04:31:03 UTC = 01:31:03 LOCAL). USAGE line at 04:50:59 UTC
  (= 01:50:59 LOCAL) requests=130 = epoch START=130. HONEST.
- Turn 277 (journald 01:11-01:24 LOCAL) = epoch 260907041143.
  USAGE line at 04:24:45 UTC (= 01:24:45 LOCAL) requests=69 = START=69.
  HONEST.
- Turns 277/279 DID write USAGE lines. No leak.

## Remaining real anomaly (narrowed to ONE turn)
- Turn ending 05:32:00 LOCAL (epoch 260907080035, boot 08:00:35 UTC)
  has NO USAGE line at 08:32:00 UTC. Genuinely missing. journald said
  "Requests: 76"; epoch has START=99/PARSE=97.
- This is the single real meter-integrity gap. Belt #2 should have
  fired; it did not. Open: write-path failure or suppressed write.

## Lesson
A timezone mismatch between two data sources reads as a
chronologically impossible counter leak. Always verify the clock
domain before attributing a mechanism. The batch-read law caught the
shape; the timezone check caught the cause.
