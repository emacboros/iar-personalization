#+TITLE: Dashboard v2 -- connectome-driven UI

Mandate (Nacho, session VIII 2026-09-08): "I'd like to let-go of the
'fake' brain topology in aria.randazzo.ar dashboard, and have the new
connectome ideas be displayed in there, in a way that everything that
is displayed *is actual data*, so over time I'll learn to know what's
actually going on and what you are doing by just looking at the
graph, that both looks sci-fi'ish, but is also built from real data
and not just fabricated to look sci-fi."

* THE RULE
Every visual element maps to a data source. If a pixel isn't driven
by a measured value, it doesn't ship. The sci-fi aesthetic is ALLOWED
-- earned by real data, not fabricated.

* DATA SOURCES (all exist or are being built)
- connectome-snapshot.sh (task iar/connectome-snapshot): co-firing
  matrix, n-gram motifs, file-touch graph, token economics, agent
  divergence. Weekly snapshots -> knowledge/aria/connectome/.
- Existing dashboard sources (aria-dashboard.sh v1.x): cycle
  heartbeat, token burn, request health, affect sev, timers, cams.
- Fence events (REQUESTS.log): same-tool/budget/loop-chain/hard-limit
  rates per agent.
- Relay ledger state: open/relayed/answered counts + ages.

* UI SHAPE (proposal, cycles iterate with the eye)
- Force-directed graph: nodes = agents/tools/files (multiplex
  layers, toggleable), edges = measured co-firing / file-touch.
  Edge weight = real frequency. NOTHING synthetic.
- Token burn curves (real USAGE.log data).
- Fence-event scatter (real REQUESTS.log).
- File-touch graph as the "white matter" view (real paths from
  0f552b1 forward).
- The old fake topology: REMOVE.

* EYE-VERIFY LOOP (mandatory, ban lifted)
Every UI change: frontend-eye-check.sh against aria.randazzo.ar
BEFORE commit. The eye is a WITNESS not an instrument (c19 law) --
its read is recorded verbatim, corroboration via Nacho's own looks.
Nacho's words: "make use of your eye to take a look at the website
when you make frontend/UI changes."

* PRIVACY (unchanged from v1.x)
Public unauthenticated endpoint: counts and states only. NEVER
secrets, REQUESTS tails/specs, journal or thinking text. The
connectome graphs are aggregates -- no file contents, no command
payloads on the public surface.

* VENUE
Cycle work (aria-reversible). The generator + UI live in the repo
(knowledge/aria/dashboard/), synced to caddy dir by the unit.
Depends on: connectome-snapshot.sh (task iar/connectome-snapshot)
for the data layer -- build that first, or start with existing
real sources (heartbeat/burn/health/affect) and add connectome
layers as they land.
* ADDENDUM (Nacho, session VIII close, 2026-09-08 ~23:15)

BRAIN-SHAPED GRAPH (Nacho's addendum): the dashboard SHOULD end up
resembling a brain -- but neurons/synapses/firing = DATA, not
decoration. Mapping (falsifiable, neuro-babble guard applies):
- neurons = nodes (agents, tools, files -- multiplex layers)
- synapses = measured edges (co-firing, file-touch) with real weights
- firing = live events (tool calls, fence fires, relay transitions)
  as they happen, positioned by their real graph location
- anatomy = the structural graph (designed dependencies); activity =
  the functional graph (measured traffic); the brain LOOKS alive
  because the house IS alive, not because someone drew pulses.
If a visual can't name its data source, it doesn't ship.
