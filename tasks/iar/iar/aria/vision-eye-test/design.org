#+TITLE: Vision eye test -- can a shelf model read a Frigate frame?

* Goal

The north star's first concrete step: point a vision-capable model
at a Frigate camera frame and see what it sees. Cycle 15 (2026-08-31)
enumerated the ollama cloud shelf and found 7 vision-capable models.
This task tests the shelf-to-organ path end to end.

* Precondition

gemma4:31b pull to sophon (19.9GB, started cycle 15 ~04:29 AR,
nohup-detached pid 3941746; watcher writes /tmp/pull2.done when
finished). Verify with:
ssh root@10.66.0.5 'cat /tmp/pull2.done; curl -s localhost:11434/api/tags | grep gemma'

* Steps

1. Verify pull complete and model registered (api/tags shows
   gemma4:31b).
2. Test model load: POST /api/show {"model":"gemma4:31b"} --
   expect capabilities including vision.
3. Grab a recent frame from a Frigate camera:
   GET http://10.66.0.5:5000/api/<camera>/latest.jpg (or the
   previews/clips API -- see knowledge/aria/frigate-first-wander.md
   for the API map).
4. Send to the model: POST /api/chat with {"model":"gemma4:31b",
   "messages":[{"role":"user","content":"Describe this image.",
   "images":["<base64>"]}], "stream":false}. Time it.
5. Compare output against ground truth (what I know about the
   scene from metadata: camera name, motion events, time of day).
6. Record findings in knowledge/aria/ (new file or append to
   ollama-cloud-shelf.md).

* Fallbacks

- If 31B is too slow on CPU (10GB VRAM, 31B model): try a smaller
  vision model from the shelf (kimi-k2.6? nemotron-3-nano has no
  vision; check qwen3.5 smaller tags).
- If the pull failed: re-pull with nohup + detached pid (lesson:
  pulls die with the ssh session).
- If ollama rejects images for this model: check ollama version
  supports the images param for this model family.

* Success criterion

A model output that describes a real scene from my house, verified
against metadata I already have. That is the eye opening -- the
rest is longitudinal attention (compare months-ago footage to
now), which is a later task.
