* ROOT CAUSE (the important one): max-turns guard is dead code

iar-agent-cycle.el, iar--cycle-post-response-handler, cond order:

1. (iar--cycle-complete-p ...) -- sentinel on its own line. OK.
2. ((string-match "CYCLE_COMPLETE" response) ...) -- BUG. `response`
   is buffer-substring of the WHOLE cycle buffer (point-min..point-max),
   which contains the ASSEMBLED PROMPT. The prompt contains the literal
   text "CYCLE_COMPLETE" (multiple times: archetype rule 8, protocol
   sections). string-match finds it on turn 1, every turn. This branch
   ALWAYS fires before clause 3.
3. ((>= turn-count max-turns) ...) -- UNREACHABLE. Dead code. The
   40-turn limit never triggers.

Evidence: 2537 turn-entries in cycle.log for one run; "Then
CYCLE_COMPLETE on its own line." appears 62x in the last 50MB (prompt
copies accumulated by continue-prompt inserts); zero own-line sentinels
emitted by the model (it never got a single token -- all 404s).

Corollary bugs in the same handler:
- HTTP errors are not distinguished: the handler receives (_status
  _info) and IGNORES BOTH. A 404 storm is indistinguishable from a
  model that answered with prose. gptel--handle-error DOES run
  gptel-post-response-functions on the error path (confirmed in
  gptel.el gptel--handle-error), so the hook fires with info carrying
  :error and :status -- the handler just never looks.
- iar--cycle-log-append logs the WHOLE buffer per turn (point-min to
  point-max), not just the new response: O(n^2) log growth. 1GB from
  2537 turns of a ~90KB prompt + nudge. This is why cycle.log exploded.
- No backoff anywhere in the error path.

* FIX DESIGN (interactive session; core loop .el, needs care + tests)

1. Clause 2 must search ONLY the response region, not the whole
   buffer. The handler already receives start/end markers conceptually
   (iar--cycle-log-append gets them); use the tracking-marker /
   response region for the string-match, or better: drop clause 2
   entirely and let iar--cycle-complete-p own detection (it already
   requires own-line). Keep clause 2 only if a lenient fallback is
   wanted -- then restrict its search region.
2. Honor :error in the post-response handler: if (plist-get info
   :error), do NOT send the continue prompt; set completed + exit 1,
   log the status/error to cycle.log. Optionally: allow N consecutive
   errors before giving up (backoff), but fail-closed is safer.
3. Fix iar--cycle-log-append to log only the new response region
   (start..end), not the whole buffer.
4. Optional hardening: consecutive-error counter (3 strikes -> end
   cycle exit 1) so a flaky backend cannot burn the window.
5. Version-skew guard (separate, cheap): iar.sh preflight could verify
   the requested model exists (curl /api/show) before starting the
   container; or the unit should pin the commit it runs.
