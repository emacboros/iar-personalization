#+TITLE: iar-loop-failure-visibility -- design

* The incident (2026-09-01)

Host /dev/null on sophon broke ~23:10-23:24 local Aug 31 (mechanism
unknown, audit-log look pending). Three symptoms, one cause:

1. sshd: "Couldn't open /dev/null: Permission denied" at 01:24:17
   (boot -2 final minutes) -> sessions refused, kex reset. This was
   the "SSH outage" of cycle 66.
2. iar.sh check_ollama: `curl -s -m 5 "http://.../api/tags" >
   /dev/null 2>&1` -- the REDIRECT failed (bash cannot open /dev/null),
   curl never ran, check returned 1. ~12 cycles skipped as "Ollama
   unreachable" 00:31-01:30 local while ollama was up (GIN log shows
   zero requests from sophon in the window, 200s from 10.66.0.1
   throughout).
3. ollama/frigate/agora-daemon: all fine (containers have their own
   /dev/null).

* The deeper failure: success-shaped failure

Loop mode summary block prints "Loop Complete / Successes: 0 /
Failures: 1" and `exit 0`. OnFailure=agent-failure@%n.service only
fires on non-zero exit. Net effect: a heartbeat that did nothing all
night reports success to systemd. The OnFailure hook (the tripwire
law, build night) never had a chance.

Also: aria-cycle.service passes no AGENT_TELEGRAM_BOT_TOKEN/CHAT_ID,
so tg_send inside iar.sh is a no-op by design (the || true swallows
everything). Every tg_send in loop mode is dead code in this
deployment. The hook is the only working notify path -- which makes
exit-code fidelity the load-bearing property.

* Fix (i.ar repo, utils/iar.sh)

1. Loop end: exit non-zero when FAILURES > 0 && SUCCESSES == 0
   (conservative: partial success still exits 0 to avoid noise).
   Alternative: exit 1 whenever FAILURES > 0 -- decide when
   implementing; prefer the conservative version first, watch a week.
2. check_ollama: stop redirecting to /dev/null. Use a tmpfile or
   `curl -fsS -m 5 -o /dev/null` is NOT enough (same failure) --
   actually test: bash failing to open the redirect target fails the
   command regardless of curl. Use `out=$(curl -fsS -m 5 ...)` and
   check $? -- command substitution does not touch /dev/null.
3. Decide tg_send fate: wire AGENT_TELEGRAM_* into the unit (needs
   Nacho's token -- for-nacho flag) or delete the dead code. Prefer
   wiring: belt-and-suspenders with OnFailure.
4. Test: differential (failure mode 8) -- simulate unreachable ollama
   with a bogus --ollama-host, verify exit 1 + OnFailure fires.

* Knowledge update

tool-call-failures map + a new failure-mode line: "a check that
redirects to a broken sink fails as a check, not as a connection
error -- the error message lies about the layer." /dev/null is load-
bearing infrastructure; its failure mode is everything-fails-quietly.
