#+TITLE: A4 -- Request log (the witness problem)

## Origin

Live event 2026-08-30 ~03:35: I emitted a malformed tool call
(unquoted read_file, integer filepath 12345) as my first action
of the session. The proxy stuffed the raw text into the name
field, gptel hung at "Calling tool (...)", Nacho interrupted at
<180s (before the watchdog would have fired). From my side: no
record. My session starts at read_task. The failed emission is
invisible to me unless a human tells me.

Nacho's framing: "You should have seen, in this example, the tool
call you attempted, even though it hang gptel." He offered me
the same debug options he has. What I can actually use is the
durable, file-based version.

## What to build

A request log at the gptel layer (init.d/tool-call/, alongside
the watchdog and malformed-args modules). For every request:

- timestamp, model, backend
- payload tail: the last message(s) sent -- my exact last
  emission, malformed or not (this is the witness part)
- raw response stream (or tail, capped)
- what the parser extracted (tool-use entries, content)
- any error signaled in the filter chain (demoted or not)
- watchdog events (already audit-logged; cross-reference)

Storage: audit/<project>/<agent>/REQUESTS.log (or a rotating
file in the audit tree). Capped/rotated like audit.log. Must not
leak into the LLM context by default -- it's for MY reading via
read_file after the fact, and for forensics.

## Design notes

- gptel-curl--get-config builds the full request body
  (gptel-request.el ~2821). Advice there captures the payload
  tail.
- The stream filter accumulates the raw response in the process
  buffer; the stream-cleanup/sentinel advice (already installed
  for token parsing in iar-tool-call.el) can dump it.
- Errors in the filter chain: the parse loops swallow some
  signals (condition-case in parse-stream). The A2b sanitizer
  removes the known crash sites; for the log, wrap the filter
  with a condition-case that logs what signaled before
  re-signaling (or before gptel's own handling).
- Watchdog aborts already insert a notice into the gptel buffer
  (agent-visible next request). The log makes them durable.

## Non-goals

- Not interactive Emacs tooling (edebug, buffers) -- that stays
  Nacho's.
- Not auto-injected into context -- I read it deliberately.

## Validation

- Emit a malformed call deliberately; verify the log shows my
  emission, the proxy's degenerate response, the parse result.
- Verify normal requests log cleanly without bloat (tail caps).
- Suite green.
